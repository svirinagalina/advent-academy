# Публичный сайт Advent Academy

Публичные страницы реализованы в существующем Next.js frontend по
`frontend/design-reference/PUBLIC_SITE_DESIGN_SPEC.md` и макетам из отдельно предоставленного ZIP. Архив не требуется для сборки сайта.
При расхождении текст и HEX спецификации имеют приоритет над концептуальными PNG.

## Маршруты и авторизация

| Адрес | Содержание |
|---|---|
| `/` | Публичная главная |
| `/courses` | Каталог, фильтры направления и подготовки в URL |
| `/courses/java` | Сравнение двух маршрутов Java |
| `/courses/java/beginner` | Требования, проект программы, практика, результаты, FAQ |
| `/courses/java/advanced` | Входная база, проект программы, сложные сценарии, FAQ |
| `/practice` | Подход к практике и учебный сценарий |
| `/practice/event-redelivery` | Разбор повторной обработки события |
| `/about` | Академия, автор и принципы |
| `/contacts` | Доступность приёма заявок и партнёрское направление |
| `/privacy` | Статус публикации документов, без выдуманного юридического текста |
| `/login` | Существующая форма входа, включая MFA |
| `/cabinet` | Существующий кабинет ученика |

Ссылки `/?view=…`, `/?course=…` и `/?lesson=…` сохранены для старых закладок.
Домашние ссылки внутри кабинетов ведут в `/cabinet`, демо остаётся на `/demo`.
«Войти» открывает `/login`; форма использует прежний `/api/session` и существующий
backend. После успешного входа открывается `/cabinet`. Отдельного хранилища токенов
или нового механизма авторизации нет. Восстановление пароля и приглашения возвращают
на `/login`. BFF, HttpOnly cookie, проверка Origin и серверные роли сохраняются.

## Публичные данные и ограничения

Каталог и программы — статическое содержание из предоставленной спецификации,
а не каталог назначенных пользователю курсов. Публичные страницы не требуют
учебных API или сессии. Программы явно обозначены как проект программы.

Владелец подтвердил отсутствие URL партнёра, контактного канала, API заявок и
утверждённой политики данных. Поэтому:

- английский обозначен как партнёрское направление Галины Свириной; активной
  ссылки без настоящего адреса нет;
- Go — информационная карточка «Скоро», без покупки, записи или выдуманной даты;
- кнопки поступления открывают окно с выбранным маршрутом; выбор маршрута и
  переход к программе работают, поля персональных данных и отправка отключены;
- форма объясняет недоступность приёма заявок, данные никуда не отправляются;
- политика не подменена образцом, нет согласия с несуществующим документом;
- цены, сроки, отзывы, показатели трудоустройства и коммерческие обещания не добавлены.

Для включения заявок нужны утверждённые условия/политика и контракт endpoint:
поля, ограничения, ошибки, подтверждение успеха и восстановление неизвестного
исхода. Это отдельная интеграция; подмены её регистрацией или приглашением нет.

## UI/UX

Публичные токены из раздела 14 ограничены `.public-site`. Голубые кабинеты используют
свои прежние токены. Тема общая через существующий ThemeProvider и сохраняется
между публичным сайтом и кабинетом на одном origin. Шрифты — уже подключённые
Golos Text и JetBrains Mono; иконки — установленный Lucide. Новых зависимостей нет.

Содержание отдаётся сервером. Нативные details сохраняют чтение программ без JS;
меню управляется клавиатурой, Escape закрывает окно и возвращает фокус. Мобильное
меню закрывается при переходе на desktop. Анимации — progressive enhancement:
без JS и при reduced motion содержание сразу видно; observer и анимации очищаются.
Фильтры записаны в URL, хлебные крошки курса возвращают применённые параметры.

Иллюстрации — подписанные учебные схемы, не снимки работающего банковского
приложения. Макеты целиком и их обрезки не используются как интерфейс или изображения
с текстом. Фотография автора не выдумана.

## Проверка

```bash
cd frontend
npm run check
npm run build
ADVENT_TEST_ORIGIN=http://127.0.0.1:3000 npm run test:public
```

Browser smoke использует существующие Playwright и Chrome. Он проверяет все десять
публичных страниц в обеих темах на 320/390/768/1024/1440 px, отсутствие переполнения,
меню и возврат фокуса, фильтры и переход назад, несколько раскрытых модулей,
недоступную отправку заявки, чтение без JavaScript и увеличение текста 200%.
Скриншоты сохраняются в `ADVENT_TEST_ARTIFACTS/public-site` либо `reports/public-site`.

При `ADVENT_EDITOR_FIXTURE` синтетического локального стенда тест проходит из
публичной шапки через настоящий вход/BFF в кабинет и управление курсами.
Проверки редактора, диалогов, администрирования и UI/UX запускаются отдельно
существующими `test:editor`, `test:dialogs`, `test:user-admin`, `test:ui-ux`,
а тема — `test:themes`.

Публикация и удалённый deployment в эту реализацию не входят. Перед публичным
приёмом заявок нужны перечисленные выше реальные данные. Проверка в Chromium
не заменяет Safari/Firefox, физические устройства и аппаратный screen reader.
