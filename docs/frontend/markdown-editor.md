# Редактирование материалов урока

В программе курса действие «Редактировать содержимое» открывает редактор, включая
пустой урок. Markdown редактируется в CodeMirror 6; HTML доступен только для чтения
и копирования. Вкладки сохраняют исходник, выделение и Undo. Вкладка «Предпросмотр» показывает готовый материал в оформлении ученической
страницы и скрывает исходник. На экране от 1000 px можно явно включить
«Markdown и предпросмотр рядом» во вкладке Markdown; по умолчанию режим выключен.
Переход в «Предпросмотр» всегда показывает только результат, даже если режим рядом включён. Диалог использует темы приложения,
ограничивает прокрутку страницы, удерживает фокус и подтверждает закрытие при
несохранённых изменениях. Вкладки поддерживают стрелки, Home и End; Tab позволяет
выйти из CodeMirror к остальным элементам диалога.

Панель вставляет разметку в текущее выделение или позицию курсора. Импорт `.md`
в диалоге подтверждает замену несохранённого текста и сохраняет Undo. Текущий
исходник можно скачать даже после ошибки или конфликта. Изображение загружается
через существующий multipart API и вставляется как `asset:<uuid>` автоматически.
ZIP по-прежнему импортируется в пустой урок через панель материала после закрытия
редактора. Повторная загрузка через старый импорт сохраняет ответ 409; существующий
материал меняется в редакторе, без повторной загрузки файла.

## JSON API

Все пути ниже начинаются с `/api/lessons/{lessonId}/content/draft`:

| Метод и суффикс | Запрос | Ответ |
| --- | --- | --- |
| GET | — | `{markdown, html, version, published}` |
| PUT | `{markdown, version}` | Сохранённая редакция с новой версией |
| POST `/preview` | `{markdown}` | Исходник и очищенный сервером HTML без сохранения |
| POST `/publish` | `{version}` | Опубликованная сохранённая редакция с новой версией |

`published` означает наличие версии, доступной ученику. Это не признак того,
что текущий черновик совпадает с ней. Пустой урок читается как версия 0;
исторический импорт без отдельного черновика — как версия 1. Клиенты должны
передавать полученное значение, а не вычислять его самостоятельно. Пустой черновик
можно сохранять; публикация пустого Markdown возвращает 400.

Права проверяются по владельцу компонента конкретного урока, с существующим
исключением для ADMIN/CONTENT_EDITOR. INSTRUCTOR не получает доступ к чужому
черновику, предпросмотру, сохранению и публикации. Обычный ученик не получает
доступ к этим маршрутам. Существующие маршруты импорта и скачивания сохранены.
Старый POST `/content/publish` остаётся для материалов старого импорта; после
появления редакторского черновика он возвращает 409, требуя версионную публикацию.

BFF разрешает только конкретные маршруты и методы, сохраняет проверку Origin,
сессионную авторизацию и `no-store`. Gateway уже маршрутизирует `/api/lessons/**`.
Markdown ограничен существующим валидатором 5 MiB UTF-8; JSON в BFF и прямом
content-service ограничен 32 MiB, включая запросы без Content-Length (запас для
JSON escape-последовательностей). Изображения используют прежний лимит 10 MiB.
Прямой сервис использует bearer JWT и существующую stateless security policy.

## Хранение и публикация

V11 добавляет `content.lesson_drafts` с исходником, HTML и числовой версией.
`lesson_contents` сохраняет прежнюю роль снимка для ученика. Миграция не удаляет
и не переписывает существующий Markdown/HTML. Чтение редактора предпочитает
черновик, иначе использует прежнюю запись, иначе возвращает пустой исходник.

Сохранение меняет только `lesson_drafts`. Публикация в одной транзакции обновляет
снимок `lesson_contents` и увеличивает версию черновика. Markdown остаётся
исходником; сервер заново проверяет вложения, рендерит и очищает HTML тем же
рендерером, что и импорт. В исходнике сохраняются `asset:` ссылки; в HTML они
разрешаются в адреса скачивания. Канонические ссылки из старого импорта также
проверяются на принадлежность уроку.

Изменения сериализуются блокировкой строки урока, в том числе первое сохранение,
старый импорт и старая публикация. После блокировки сервер сравнивает версию:
устаревший запрос получает 409 до изменения данных. Клиент сохраняет свой текст,
останавливает повторное сохранение и предлагает скачать его, открыть актуальную
редакцию и перенести изменения. При сетевой ошибке исходник остаётся в окне.
Устаревшие ответы предпросмотра игнорируются; HTML от прежнего текста не выдаётся
за актуальный и не предлагается для копирования.

Вложения, загруженные после опубликованного снимка, доступны владельцу компонента,
загрузившему пользователю и куратору,
но не добавляются к материалу ученика до следующей публикации. Для этого чтение
сравнивает время создания вложения со временем снимка. V11 сохраняет видимость
исторических вложений, сдвигая время старого опубликованного снимка до времени
его последнего вложения, если это необходимо.

## Проверки

### Ученический урок и состояния форм

Опубликованный материал, сохранённый предпросмотр и предпросмотр редактора
используют общий `LessonMaterial`. Поддержана подсветка Java, JavaScript,
TypeScript, Python, SQL, HTML/XML, CSS, JSON и Bash (включая зарегистрированные
библиотекой алиасы). Неизвестный язык и блок без языка отображаются обычным
кодом. Для блоков больше 100 000 символов подсветка отключается, исходник,
нумерация и копирование сохраняются.

Номера строк декоративные и не попадают в исходник при копировании. Кнопка
«Копировать код» копирует точный текст, включая завершающий перевод строки.
Блок доступен с клавиатуры и прокручивается внутри собственной области.
Цвета подсветки наследуют токены активной темы. Сервер по-прежнему очищает HTML;
клиентская подсветка получает только `textContent` блока, а не исходный HTML.

«Открыть задание» из главной и списка, а также ссылка с `assignment=1`, ждут
загрузки реального задания, прокручивают к его заголовку и переводят на него
фокус. После начальной ошибки доступен повтор. Обновление статуса не возвращает
фокус на заголовок и не запускает повторную прокрутку.

Видео использует нативные контролы в области 16:9, реальные метаданные,
состояние загрузки и ошибку с кнопкой повтора. Воспроизведение не завершает урок.
Вложения скачиваются с проверкой HTTP-ответа; при ошибке показаны сообщение и
повтор, при успехе сохраняется имя файла. Урок при скачивании не закрывается.

Формы курса, модуля, урока, выбора модуля и сдачи решения имеют отдельные ошибки
полей, `aria-invalid`/`aria-describedby` и состояния запроса. Общая ошибка сети
не помечает корректное поле как невалидное. Серверный ответ валидации сохраняет
`message: "Invalid request"` и добавляет `fieldErrors` с кодами ограничений;
введённые значения в ответ не включаются. Данные формы при ошибке сохраняются.

`npm run test:lesson-design` проверяет эти сценарии через реальные сервисы
и включён в `test:editor:local` после проверок редактора и диалогов.
Для отдельного запуска нужны переменные `ADVENT_TEST_ORIGIN`,
`ADVENT_EDITOR_FIXTURE`, `ADVENT_TEST_GATEWAY`, `ADVENT_TEST_POSTGRES`,
`ADVENT_TEST_PROJECT`, `ADVENT_TEST_ARTIFACTS`, которые задаёт оркестратор.
Перед подготовкой обязательного задания тест проверяет принадлежность контейнера
Compose-проекту и tmpfs PostgreSQL. Изменяется только созданный тестом урок.
Синтетический `frontend/scripts/fixtures/lesson-video.mp4` — полсекунды цвета,
без звука; внешний видеосервис и FFmpeg для запуска теста не требуются.

### Автоматический локальный запуск

Из корня репозитория:

```sh
python3 scripts/editor-e2e.py
```

Эквивалент из `frontend/`: `npm run test:editor:local`.

Нужны Linux, Python 3.10+, JDK 21 (`JAVA_HOME`), Node.js 24 с npm,
работающий Docker Engine и Compose v2 с поддержкой `up --wait`.
При первом запуске необходим доступ к реестрам Gradle, npm и Docker.
Скрипт сам выполняет `npm ci`, поэтому предварительно устанавливать зависимости
frontend не требуется. Для браузера можно установить Google Chrome по пути
`/usr/bin/google-chrome`, задать `CHROME_PATH` или установить Chromium Playwright:

```sh
cd frontend
npm ci --no-audit --no-fund
npx playwright install --with-deps chromium
```

Один запуск выполняет:

1. Сборку актуальных JAR четырёх сервисов, установку frontend-зависимостей,
   проверку браузера, lint, typecheck и production-сборку frontend.
2. Запуск отдельного Compose-проекта `advent-editor-e2e-<timestamp>-<id>`
   из `docs/backend/runtime-editor-e2e.yml`: PostgreSQL в tmpfs,
   user/content/meeting-service и gateway. Образы собираются из текущих JAR.
3. Ожидание readiness сервисов, регистрацию синтетических пользователей через
   API, подтверждение почты и выдачу ролей в одноразовой БД. Перед SQL проверяются
   Compose project/service labels и наличие tmpfs у PostgreSQL.
4. Запуск production frontend на свободном loopback-порту и ожидание `/api/health`.
   Gateway также публикуется на автоматически выбранном loopback-порту.
5. Последовательный запуск `test:editor`, `test:dialogs`, `test:lesson-design`:
   второй сценарий использует опубликованный курс, созданный первым; третий
   создаёт отдельный урок с заданием, видео, кодом и вложением.
6. Остановку frontend и удаление контейнеров, сети, томов и образов текущего
   тестового проекта. Очистка выполняется при успехе, ошибке, Ctrl+C и SIGTERM.

Основная локальная БД, корневой `.env` и другие Compose-проекты не используются.
Каждый повторный запуск получает новый проект, БД, пользователей и каталог
артефактов. Сборочные каталоги и `node_modules` в checkout используются повторно;
не запускайте команду одновременно из одного checkout.

Артефакты остаются в `reports/editor-e2e/<timestamp>-<id>/` и исключены из Git
и Docker build context:

- `backend-build.log`, `npm-ci.log`, `frontend-check.log`, `frontend-build.log`;
- `compose-up.log`, `compose-services.log`, `compose-ps.log`, `cleanup.log`;
- `frontend.log`, `editor.log`, `dialogs.log`, `lesson-design.log`;
- `fixture.json` с синтетическими учётными данными и `result.json` с итогом;
- `browser/editor/`, `browser/dialog/`, `browser/lesson-design/`: скриншоты страниц при закрытии контекста,
  traces, сообщения консоли и `failure.log` при ошибке сценария.

Каталог создаётся с правами только для текущего пользователя. Traces могут
содержать тестовые токены и данные запросов. Открыть trace:
`cd frontend && npx playwright show-trace <абсолютный-путь-к-trace.zip>`.
Ошибка любого этапа или очистки возвращает ненулевой exit code. При ошибке
очистки команда для повторного `docker compose ... down` выводится в stderr.
После SIGKILL или отключения питания автоматическая очистка невозможна; имя
проекта есть в `result.json` (если записан) и в имени каталога. Ручная очистка:

```sh
docker compose --env-file /dev/null -p advent-editor-e2e-<timestamp>-<id> \
  -f docs/backend/runtime-editor-e2e.yml down --volumes --remove-orphans --rmi local
```

Артефакты при очистке стенда сохраняются. Ненужный каталог запуска можно удалить
вручную. Подключение сценариев к GitLab CI остаётся отдельной задачей.

Проверки защитных условий подготовки БД и обработки ошибок оркестратора
запускаются без Docker: `python3 -m unittest discover -s scripts -p test_editor_e2e.py`
из корня репозитория.

Docker 29.1.3 и Compose 2.27.0:

  `reports/editor-e2e/20261016-122525-56489d7c/`.
  В каждом прошли редактор и все шесть сочетаний темы/ширины для диалогов.
- В отдельном запуске `20261016-122700-5facd1ee` намеренно подменён браузерный
  этап сценарием с исключением после открытия страницы. Оркестратор вернул 1,
  сохранил PNG, trace и ошибку, удалил контейнеры и группу процессов frontend.
  Подмена использовалась только в проверочном процессе, в коде команды её нет.

Browser fixture: `{password, users: {editor: {email, id}, student: {email, id},
foreign: {email, id}}}`. Нужны подтверждённые активные аккаунты,
CONTENT_EDITOR у editor и INSTRUCTOR у foreign. В стандартной миграции ролей
CONTENT_EDITOR отсутствует: для этого сценария роль и назначение создаются
только в одноразовой тестовой БД. Скрипт сам создаёт курсы/уроки и назначает
ученика через существующий API; повторный запуск создаёт новые тестовые курсы.

## Центрирование и режимы предпросмотра

Все типы native dialog используют общее центрирование по обеим осям, включая
редактор и программу курса. Мобильный редактор занимает экран целиком; остальные
окна ограничены высотой viewport и прокручиваются внутри.

`npm run test:dialogs` проверяет геометрию центра (допуск 2 px), отсутствие
горизонтального переполнения, закрытие по Escape и переключение предпросмотра
на ширинах 1440/390/320 в обеих темах. Покрыты формы курса/модуля/урока, выбор
модуля, удаление из программы, архивация, редактор материала, форма занятия,
детали занятия и мобильная программа курса. Используются те же переменные
ADVENT_TEST_ORIGIN и ADVENT_EDITOR_FIXTURE, что и в test:editor.

Предпросмотр и панель материала используют классы lesson-article/lesson-material
ученической страницы: отступы абзацев, адаптивные заголовки и оформление кода.
Лог проверки окон: `/tmp/advent-dialog-browser.log`.
