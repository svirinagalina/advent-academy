# Спринт 2: сдача и проверка заданий

Статус: AA-06–AA-09 реализованы. Зависит от AA-01–AA-05 первого спринта.

## Этапы и готовность

| Задача | Зависимость | Результат | Проверка готовности |
|---|---|---|---|
| AA-06 — Условия и история попыток | AA-03, AA-04 | Условие обязательного задания, immutable попытки, миграция | Старые данные сохранены; чужой пользователь не читает попытки |
| AA-07 [BLOCKED BY AA-06] — Сдача и повторная отправка | AA-06 | HTTPS-ссылка, комментарий, idempotency requestId; повтор после changes | Повторы/гонки не создают дубликатов; некорректная ссылка отклоняется |
| AA-08 [BLOCKED BY AA-07] — Проверка и завершение | AA-07 | Очередь/история преподавателя, обратная связь, accepted/changes | Чужой преподаватель и сам ученик не проверяют; принятие атомарно завершает урок |
| AA-09 [BLOCKED BY AA-08] — Экраны и полный сценарий | AA-08 | Форма в уроке, мои задания, главная, очередь проверки | Browser: сдача → доработка → повтор → принятие → следующий урок, перезапуск и ошибки |

Работа остаётся в content-service и существующем Next.js. Расписание/звонки,
уведомления, загрузка файлов решений, автоматический запуск кода и новые сервисы вне спринта.

## Правила

- Только обязательные задания (`required_assignment=true`); условие задаёт владелец компонента/редактор.
- Для ранее опубликованных уроков условие можно добавить без перепубликации. После первой сдачи
  условие неизменно; менять обязательность после публикации по-прежнему запрещено.
- Личность ученика/проверяющего берётся из JWT, не из тела запроса.
- Проверка доступна владельцу курса с ролью INSTRUCTOR, ADMIN или CONTENT_EDITOR.
  Проверка собственной работы запрещена даже администратору.
- Ссылка — абсолютный HTTPS URL без логина/пароля. Backend не скачивает решение.
- Статусы попытки: review → changes или accepted. После changes разрешена новая попытка;
  при review/accepted новые попытки запрещены. Черновик формы — только локальный, отдельно для пользователя/урока.
- RequestId UUID сохраняется при повторе запроса; тот же ключ с другим содержимым даёт 409.
- Каждая попытка сохраняет исходную ссылку/комментарий и результат; очередь не заменяет историю.
- Проверка использует version. Точный повтор одного решения тем же проверяющим успешен;
  конфликтующие решения дают 409. Комментарий при changes обязателен.
- Порядок блокировок: назначение ученика → урок/попытка. Принятие и learning_completions
  фиксируются одной транзакцией. Отказ/ошибка откатывает всё.
- Очередь преподавателя постраничная. Ученик видит только свои назначенные опубликованные курсы.
- У старого обязательного урока без условия показывается «Условие пока не добавлено», сдача запрещена.

## Контракты

| Метод | Путь | Доступ |
|---|---|---|
| PUT | /api/lessons/{lessonId}/assignment | Владелец компонента/редактор; title, description |
| GET | /api/learning/assignments | Собственный список заданий со статусом и доступностью |
| GET | /api/learning/courses/{courseId}/lessons/{lessonId}/assignment | Условие и собственные попытки доступного урока |
| POST | /api/learning/courses/{courseId}/lessons/{lessonId}/submissions | Собственная сдача: requestId, url, comment |
| GET | /api/teaching/submissions?status=review&page=0&size=20 | Владелец курса/редактор; очередь и история |
| GET | /api/teaching/submissions/{submissionId} | Детали попытки разрешённого курса |
| POST | /api/teaching/submissions/{submissionId}/review | version, status (changes/accepted), feedback |

Ошибки: 400 — валидация, 401 — сессия, 403 — права, 404 — отсутствует объект,
409 — заблокированный урок/неверный переход/конкурентное решение/повтор ключа с другим payload.

## Запуск проверки

Из корня, на отдельном тестовом стенде (рабочий PostgreSQL не используется):

```bash
./gradlew :user-service:bootJar --no-daemon
docker build -f user-service/Dockerfile -t advent-sprint2-user .
docker build -f content-service/Dockerfile -t advent-sprint2-content .
docker build -f api-gateway/Dockerfile -t advent-sprint2-gateway .
docker build -f frontend/Dockerfile -t advent-sprint2-frontend .
docker compose -p advent-sprint2 -f docs/frontend/runtime-compose-sprint2.yml up -d --wait
ADVENT_TEST_PROJECT=advent-sprint2 python3 frontend/scripts/provision-runtime.py
cd frontend
npm ci
ADVENT_TEST_ORIGIN=http://localhost:13009 ADVENT_TEST_FIXTURE=/tmp/advent-sprint2-fixture.json npm run test:runtime
npm run test:assignments
```

Для повтора нужен свежий стенд: тест изменяет прогресс синтетических учеников.
Остановка из корня:

```bash
docker compose -p advent-sprint2 -f docs/frontend/runtime-compose-sprint2.yml down
```

БД в tmpfs, порты 13009/18091. Скрипт проверяет название Compose-проекта и tmpfs
перед записью. При подготовке аккаунтов автор курса временно получает роль ADMIN
для создания контента, затем остаётся обычным INSTRUCTOR. Проверка очереди использует
реальный вход и JWT этого преподавателя. Уведомления/polling не добавлены: результат
обновляется кнопкой «Обновить статус» и при повторном открытии урока.

Сдача: `requestId`, `url`, `comment`. Ответ включает title/description и все попытки
по возрастанию attempt: id/userId/courseId/lessonId/attempt/url/comment/status/feedback/
reviewerId/submittedAt/reviewedAt/version. Версия первой сдачи 0, после проверки 1.
Queue: items + total/page/size; item содержит submission и название курса/урока/условие.
Точный повтор решения отправляется с исходной version. BFF ограничивает body 32 KiB.

## Результаты проверки (2026-10-14)

- Все этапы AA-06–AA-09 завершены.
- content-service: 275 тестов (8 новых интеграционных сценариев), user-service: 206,
  api-gateway: 13. Ошибок/пропусков нет. SecurityContract: 10 тестов, успешно.
- Checkstyle/SpotBugs/assemble прошли; Biome/TypeScript прошли; Docker production
  frontend build и сборки всех четырёх сервисов успешны. Изолированный стек healthy.
- PostgreSQL: доработка/повтор/принятие, сохранение истории, версии/повторы запросов,
  конкурирующие сдачи и решения, запрет чужих данных/собственной проверки,
  валидация и старое задание без условия проверены. Ошибка после вставки завершения
  откатила и статус попытки, и прогресс; повтор затем успешно принял работу.
- Playwright: реальный вход ученика и обычного INSTRUCTOR-владельца,
  потерянный ответ после commit и повтор без дубликата, доработка/вторая попытка/
  принятие/следующий урок, отдельные черновики при смене аккаунта, история,
  фильтры, мобильные экраны и повторный вход прошли.
- Дополнительные регрессии: повтор той же ссылки после потери ответа + reload +
  changes создаёт новую попытку; доступное задание появляется на главной после
  завершения предыдущего урока при навигации в том же сеансе.
- Сценарий первого спринта на финальном образе прошёл.
- BFF: чужой Origin → 403, большой body → 413, в том числе chunked без Content-Length.
- V10 применена в транзакции к копиям заполненных таблиц V9: курсы, уроки,
  назначения и прогресс сохранены; неожиданных сдач нет. Проверка откачена.
- git diff --check прошёл. Временный стенд после проверки удалён.

Границы: проверка на синтетических данных и временном PostgreSQL, Camunda отключён;
production-развёртывание и несколько экземпляров BFF не проверялись. Ограничение
одного standalone-процесса и условия опубликованных assets из спринта 1 сохраняются.
