# Advent Academy — кабинет управления курсами

Дополнение к утверждённой дизайн-системе. Основные экраны ученика и DESIGN_SPEC.md не изменяются. Это дизайн и поведение frontend; конкретные URL, DTO, ограничения размеров файлов и серверные условия публикации сверяются с готовыми API, поскольку их схема в задании не предоставлена.

## 1. Роли и область доступа

| Действие | ADMIN | CONTENT_EDITOR | INSTRUCTOR |
|---|---|---|---|
| Список курсов | Все курсы | Все курсы | Только доступные существующие |
| Создать курс | Да | Да | Нет: кнопку и форму скрыть |
| Открыть / управлять курсом | Любой курс | Любой курс | Только доступный курс |
| Название, описание, структура | Только черновик | Только черновик | Только доступный черновик |
| Создать модуль | Да, в редактируемом контексте | Да, в редактируемом контексте | Нет: кнопку и форму скрыть |
| Создать урок в модуле | При праве управления модулем и его статусе черновика | При праве управления модулем и его статусе черновика | Только в собственном модуле-черновике; владение курсом не передаёт права на чужой общий модуль |
| Загрузить и публиковать материал | По разрешениям API | По разрешениям API | По разрешениям API доступного курса |
| Найти и назначить ученика | Только опубликованный курс | Только опубликованный курс | Только доступный опубликованный курс |

«Управляет курсом» трактуется как доступ к указанным в задании операциям в рамках разрешённого курса. Точные права на отдельные модули, уроки и материалы должны подтверждаться API; наличие связи с курсом не доказывает права на любой общий модуль.

Для пользователя роли отображаются как «Администратор», «Редактор контента», «Преподаватель». Внутренние значения ролей — ADMIN, CONTENT_EDITOR, INSTRUCTOR.

Недоступное по роли действие отсутствует в интерфейсе. Доступное по роли, но временно невозможное по состоянию действие может быть disabled с видимой причиной. Скрытие кнопок не заменяет серверную авторизацию. Переход по чужому идентификатору курса при ответе отказа показывает «Нет доступа к этому курсу» и «К доступным курсам»; название и содержимое чужого курса не раскрываются.

## 2. Статус курса

| Статус | Название, описание и программа | Ученики | Публикация / архив |
|---|---|---|---|
| Черновик | Редактирование при наличии права управления | Просмотр вкладки; поиск и назначение скрыты; пояснение «Назначение учеников станет доступно после публикации курса» | «Опубликовать курс» при доступности; причины блокировки рядом |
| Опубликован | Только просмотр: скрыты поля редактирования, добавление, перемещение и удаление модулей | Список назначенных; поиск и назначение доступны | Публикацию повторно не показывать; «Архивировать курс» при разрешении API |
| Архив | Только просмотр и сообщение «Курс в архиве» | Список назначенных доступен при соответствующем API; поиск и назначение скрыты | Ни повторной публикации, ни восстановления в интерфейсе |

Переходы базовой концепции: Черновик → Опубликован → Архив. Другие переходы не придумываются. Возможность архивирования черновика не заявляется.

Публикация материала, модуля и курса — три разные операции. В макетах показаны причины «Опубликуйте материалы уроков» и «Сначала опубликуйте модули программы». Это предлагаемый порядок из основного сценария. Обязательность и точные условия этих блокировок сверяются с API; не рассчитывать готовность только по предположениям frontend.

Не обещать, что архивирование автоматически удалит назначения, остановит обучение или изменит доступ ученика: такие последствия в задании не определены.

## 4. Список курсов

Заголовок «Курсы» у ADMIN / CONTENT_EDITOR и «Доступные курсы» у INSTRUCTOR. Каждая строка содержит название, описание, текстовый статус и переход «Открыть курс». Статусы снабжаются значком и не передаются одним цветом.

«Создать курс» только у ADMIN / CONTENT_EDITOR. Простая фильтрация: Все / Черновики / Опубликованные / Архив. На мобильном фильтры переносятся на следующие строки; карточки вертикальные. Преподавателю не оставлять пустое место под отсутствующей кнопкой.

Состояния:
- Загрузка: skeleton карточек и aria-busy.
- Пустой список у редактора: «Курсов пока нет» и «Создать курс».
- Пустой список у преподавателя: «Нет доступных курсов» и объяснение «Здесь появятся курсы, к которым вам предоставлен доступ»; без создания курса.
- Пустой фильтр: «В этой категории пока нет курсов», возврат к «Все».
- Ошибка: «Не удалось загрузить курсы» и «Повторить». Фильтр сохраняется.

## 5. Создание курса, модулей и уроков

### Курс

Окно «Создать курс»: название, описание, «Создать курс», «Отмена». Название обязательно. Ограничения длины и обязательность описания берутся из API, не вводятся произвольные значения.

Во время запроса кнопка показывает «Создаём…», повтор заблокирован. При ошибке текст сохраняется. После успешного создания открывается карточка нового черновика. Серверные ошибки полей показываются рядом с полями, общая ошибка — над действиями.

### Модуль

«Создать модуль» открывает форму с названием и кнопкой создания. После создания модуль существует как самостоятельный черновик. Для включения в курс требуется операция добавления в программу: интерфейс предлагает добавить созданный модуль, но не сообщает об успешном включении до ответа API. Если API уже поддерживает создание со связью, использовать его контракт без второго запроса.

Не добавлять клонирование, импорт каталогов или специальные настройки доступа.

### Существующий модуль

«Добавить существующий модуль»: окно со списком доступных модулей, названиями и статусами. Выбор и действие «Добавить в программу». Уже включённый модуль помечается «Уже в программе», повторная операция скрыта. Добавление доступно только в черновике курса.

Учитывать отдельные состояния загрузки, пустого списка и ошибки. Если доступ к модулю отозван, показать причину и обновить список.

### Урок

«Создать урок» внутри доступного редактируемого модуля: название, кнопка «Создать урок», «Отмена». После подтверждения открыть экран материала нового урока в состоянии «Материал не загружен».

Урок не считается опубликованным после создания. Не добавлять встроенную IDE или rich-text редактор.

## 6. Карточка курса и программа

Верх: возврат к курсам, название, статус и применимое действие жизненного цикла. Вкладки «Программа» / «Ученики» доступны без изменения данных при переключении.

Редактирование названия и описания — форма с отдельным «Сохранить изменения», только в черновике. Mobile использует кнопку «Изменить название и описание», открывающую полноширинную панель формы. Во время сохранения показывать ожидание; при ошибке сохранять ввод.

Модули раскрываются; видны уроки и отдельные статусы материалов. Нажатие на урок / «Материал урока» ведёт к просмотру и управлению его материалом в рамках прав.

Порядок модулей:
- Кнопки «Выше» / «Ниже»; крайние направления недоступны.
- На desktop допустим drag-handle только как дополнительное действие; кнопки остаются обязательным способом для клавиатуры и мобильных устройств.
- После перемещения сохраняется порядок через API. На время запроса блокируются конкурирующие перемещения.
- При ошибке порядок возвращается к последнему подтверждённому; пояснение «Не удалось изменить порядок. Попробуйте ещё раз».

Удаление из программы:
- Точное действие «Убрать из программы».
- Подтверждение «Убрать модуль “Основы Java” из программы курса?».
- Пояснение «Модуль и его уроки сохранятся».
- Удаляется связь с курсом, не глобальный модуль.
- До успешного ответа строка не исчезает либо явно отмечается ожидание.

Публикация и архивирование используют отдельные запросы, состояние ожидания и подтверждённый сервером статус. При ошибке старый статус сохраняется. При архивировании показывается подтверждение без неподтверждённых обещаний о последствиях.

Общий модуль может использоваться несколькими курсами. Эта концепция не утверждает, что изменение такого модуля затрагивает только текущий курс. Права и статус самого модуля учитываются дополнительно к статусу курса.

## 7. Материал урока: .md / ZIP → HTML → черновик → публикация

| Состояние | Интерфейс | Доступные действия |
|---|---|---|
| Материал отсутствует | Выбор файла, поддержка .md / ZIP с Markdown и вложениями | «Выбрать файл», затем «Загрузить материал» |
| Файл выбран локально | Имя файла | Убрать локальный выбор до отправки; это не удаление серверного материала |
| Передача / обработка | «Загружаем материал…», затем «Подготавливаем HTML…», если API различает этапы | Повторная отправка заблокирована |
| Успех | «Материал загружен. HTML подготовлен и сохранён как черновик» | Предпросмотр; отдельное «Опубликовать материал» при праве |
| Предпросмотр | Серверный очищенный HTML, текст, код и вложения | Просмотр; без редактора и без автоматической публикации |
| Публикация | «Публикуем…» | Повторная публикация заблокирована |
| Опубликован | Статус «Опубликован» | Предпросмотр; без повторной публикации или замены |

Если API не предоставляет прогресс передачи, использовать индикатор без придуманных процентов. Если ответ API единственный после всей обработки, показывать единое «Загружаем и подготавливаем материал…» вместо выдуманной двухфазной обработки.

Превью отображает результат сервера. Не считать HTML предварительным локальным преобразованием Markdown. Не выполнять скрипты или сторонние активные вставки в предпросмотре.

После появления контента в уроке: «Повторная загрузка в этот урок пока не поддерживается». Кнопки «Заменить», «Загрузить новую версию» и рабочая зона повторного upload отсутствуют.

Ошибки:
- Неверное расширение: «Выберите файл .md или ZIP с Markdown и вложениями».
- Некорректный ZIP: «Не удалось прочитать архив. Проверьте ZIP-файл».
- Markdown в архиве отсутствует: «В архиве не найден Markdown-файл».
- Не удалось преобразовать: «Не удалось подготовить HTML. Проверьте Markdown и вложения».
- Файл превышает ограничение: показать реальное ограничение из API, не выдумывать число.
- Материал уже существует: убрать upload и перейти к текущему материалу; повторная загрузка не предлагается.
- Сетевая ошибка: «Не удалось загрузить материал. Проверьте соединение и попробуйте ещё раз».
- Неопределённый исход отправки: сначала проверить, появился ли материал в уроке. Повторять upload только после подтверждения его отсутствия, чтобы не имитировать замену.
- Ошибка preview: «Не удалось загрузить предпросмотр» / «Повторить».
- Ошибка публикации: «Не удалось опубликовать материал» / «Повторить»; черновик сохраняется.

Разрешение загрузки / публикации материала при опубликованном курсе в исходных требованиях не определено. Никакое дополнительное право на изменение опубликованного контента не заявляется; доступность операций определяется контрактом API. Основной макет загрузки показывает черновик курса.

## 8. Ученики: назначенные и кандидаты

Вкладка всегда объясняет применимое состояние:
- Черновик: «Назначение учеников станет доступно после публикации курса». Поле поиска и назначение скрыты.
- Архив: «Курс в архиве. Поиск и назначение учеников недоступны». Просмотр существующих назначений при доступности API.
- Опубликован: список назначенных + поиск кандидатов.

Назначенные ученики: имя и email; без удаления, приглашения по email, аналитики или изменения ролей. Пустое состояние: «На курс пока никто не назначен».

Поиск:
- Метка «Имя или email».
- До 2 символов после удаления крайних пробелов запрос не отправляется; подсказка «Введите минимум 2 символа».
- Поиск по вводу с предлагаемой задержкой 300 мс. Это поведение frontend, не требование к API.
- Максимум 20 результатов. Нет искусственной пагинации, если её не поддерживает API.
- Устаревшие ответы для предыдущего запроса игнорируются.
- Пустой результат: «Никого не нашли. Попробуйте другое имя или email».
- Загрузка: индикатор в зоне результатов; введённый запрос сохраняется.
- Ошибка: «Не удалось найти учеников» и «Повторить».
- Уже назначенный человек: галочка и «Уже назначен», без рабочей кнопки назначения.
- Назначение на строке: «Назначаем…», защищено от повторного нажатия.
- Успех только после ответа API: человек добавляется в назначенные; соответствующий результат поиска получает «Уже назначен»; сообщение «Мария Кузнецова назначена на курс».
- Ошибка назначения показывается на строке; ученик не добавляется преждевременно.
- Ответ «уже назначен» синхронизирует оба списка, не создаёт дубль.
- Если курс стал архивным или доступ отозван, поиск и назначение закрываются по актуальному состоянию.

Mobile:
- Ориентир 390 CSS px; полноразмерные русские подписи, поля 16 px.
- Список курсов — карточки; назначенные и кандидаты — вертикальные строки с email под именем.
- Программа — раскрывающиеся модули; действия переносятся на строки, порядок доступен кнопками «Выше / Ниже».
- Формы создания, изменения названия и выбора модуля — полноширинные панели; submit доступен без перекрытия клавиатурой.
- Upload — выбор файла, без обязательного drag-and-drop.
- Preview на отдельном экране материала после успешной загрузки; длинный код прокручивается только внутри блока.
- Скрытие кнопок по роли не заменяется disabled-заглушкой.
- До 1023 px отсутствует desktop-меню, возврат и навигация через верхнюю панель; единственный основной раздел — курсы.
- Мобильный кабинет управления не использует ученическую нижнюю навигацию «Задания / Занятия»: этих разделов здесь нет.

Доступность:
- Кнопки и значки с областью минимум 44×44 CSS px.
- Видимый focus-visible, клавиатурные кнопки перестановки, постоянные метки полей.
- Вкладки: активное состояние, корректный порядок фокуса; модальные панели закрываются крестиком, Escape и фоном, удерживают фокус и возвращают его к инициатору.
- Текст ошибок связан с полем / действием, статус сопровождается текстом и значком.
- Нет горизонтального скролла страницы; длинные названия и email переносятся.
- При увеличении текста карточки и строки растут по содержимому.
- Проверка контраста и доступности будущей реализации требуется отдельно; соответствие стандарту не заявляется.

## 11. Границы реализации и данные API

Frontend нужны существующие операции получения разрешённых курсов, создания курса, изменения черновика, чтения и изменения программы, работы с модулями и уроками, загрузки и чтения материала, отдельных публикаций, архивирования, поиска и назначения учеников.

Не выдумывать endpoint-адреса. Минимальные сведения для отображения:
- Курсы: идентификатор, название, описание, статус и доступные операции.
- Программа: идентификаторы, порядок и названия модулей/уроков; статусы соответствующих объектов.
- Материал: наличие, статус, очищенный HTML и ссылки вложений; ошибка преобразования при наличии.
- Ученики: идентификатор, имя, email; уже назначен — по ответу поиска или по подтверждённому списку.
- Публикация: актуальный статус, готовность и причины отказа.
Если capabilities не возвращаются явно, использовать согласованное отображение ролей и статусов, а все действия всё равно подтверждать сервером.

Открытые уточнения перед реализацией:
1. Точные требования API к публикации материала, модуля и курса.
2. Права и последствия изменения модуля, используемого несколькими курсами.
3. Доступность загрузки / публикации материала вне черновика курса.
4. Структура допустимого ZIP, выбор основного Markdown при нескольких файлах, ограничения размера и вложений.
5. Семантика архивирования для уже назначенных учеников.
Эти вопросы не блокируют дизайн основных состояний, но не должны заменяться выдуманным поведением frontend.



## 12. Дополнение: связанные публикации, формы и обычная вкладка учеников

### Связанные причины блокировки

Три действия остаются самостоятельными: «Опубликовать материал», «Опубликовать модуль», «Опубликовать курс». Ни одно не запускает автоматическую публикацию остальных объектов.

| Блокировка | Видимое объяснение | Переход рядом |
|---|---|---|
| Материал урока не опубликован | «Материал урока “Условные операторы” не опубликован» | «Открыть материал урока» → серверный HTML-предпросмотр и отдельная публикация материала |
| Модуль не опубликован | «Модуль “Основы Java” не опубликован» | «Открыть модуль» → раскрыть соответствующий модуль в программе |
| Несколько модулей не опубликованы | «Не опубликованы модули программы» | Отдельная ссылка к каждому препятствующему модулю |

Переход к модулю раскрывает его, прокручивает к нему и переводит фокус на заголовок. Возврат из материала сохраняет контекст программы. После подтверждения публикации готовность родительского элемента перечитывается из API. Следующее действие не активируется только по нажатию кнопки или локальному предположению об успехе.

### Формы и их состояния

Формы: создание курса; изменение названия и описания; создание модуля; создание урока; выбор существующего модуля. В интерфейсе нет технических значений ролей. Они остаются только в спецификации и пояснениях прав.

| Форма | Ошибка поля / выбора | Состояние запроса | Подтверждённый результат |
|---|---|---|---|
| Создание курса | «Введите название курса» | «Создаём…» | Открывается карточка созданного черновика |
| Изменение названия и описания | «Введите название курса» | «Сохраняем…» | «Изменения сохранены»; данные карточки обновлены |
| Создание модуля | «Введите название модуля» | «Создаём…» | «Модуль создан»; отдельное добавление в программу при необходимости |
| Создание урока | «Введите название урока» | «Создаём…» | Открывается материал созданного урока, до загрузки содержимого |
| Выбор существующего модуля | «Выберите модуль» | «Добавляем…» | Модуль появляется в программе после ответа API |

Во всех формах сетевые и серверные ошибки сохраняют ввод. Текст ошибки показывается рядом с полем или действием; повтор не очищает форму. Кнопка выполнения защищена от дублей. Обязательность описания и ограничения длины берутся из API, а не из изображения.

Во время запроса закрытие формы не должно создавать ложное впечатление отмены серверной операции. При неопределённом исходе проверяется актуальное состояние перед повтором. Подтверждённый успех закрывает форму либо показывает результат с явным возвратом к программе.

### Мобильная адаптация

Новые актуальные подписи перемещения: «Выше» и «Ниже». Первый модуль нельзя поднять выше, последний — опустить ниже. Действия доступны с клавиатуры и через области нажатия минимум 44×44 CSS px.

В списке редактора видны все курсы и «Создать курс». У преподавателя создание скрыто, список содержит только разрешённые курсы. Это варианты одного компонента, а не разные функции.

В мобильной программе заголовок, статус, действие публикации и причина блокировки располагаются вертикально. Ссылки к препятствующим элементам переносятся на несколько строк. Назначенные ученики и кандидаты — вертикальные списки: имя над email, действие ниже; табличная desktop-компоновка не уменьшается целиком.

### Обычное состояние и хронология примеров

В обычной вкладке «Ученики» нет временного уведомления об успешном назначении. Видны назначенные ученики, поиск, доступный кандидат и «Уже назначен». После нового подтверждённого назначения сообщение об успехе используется из ранее показанных состояний.

Дополнительные экраны «Ученики» демонстрируют Java после публикации курса и преподавателя с доступом к этому существующему курсу. Начальные экраны программы Java по-прежнему показывают черновик: это разные этапы сценария. Прежние экраны учеников Git остаются отдельным примером опубликованного курса. Доступ к курсу не возникает автоматически от публикации: наличие права проверяется отдельно.

Для черновика: список назначений при наличии данных и объяснение «Назначение учеников станет доступно после публикации курса»; поиск и назначение скрыты. Для архива: «Курс в архиве. Поиск и назначение учеников недоступны»; существующие назначения только для просмотра. Поиск опубликованного курса: от двух символов, максимум 20 результатов, с загрузкой, пустым ответом, ошибкой и повтором.

Последовательность: создать черновик курса → собрать программу → создать уроки → загрузить материалы → опубликовать материалы → опубликовать модули → опубликовать курс → найти ученика → назначить после подтверждения API. Условия готовности публикации по-прежнему определяются сервером.
