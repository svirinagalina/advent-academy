## 1. Назначение и зафиксированные решения

Многостраничный сайт молодой академии. Главная помогает выбрать направление и маршрут; страница курса объясняет входные требования, содержание, практику и способ подачи заявки.

Доступные направления в концепции: Java и английский у партнёра Галины Свириной. Java разделена на два маршрута: «Java с нуля» и «Java Advanced». Это два предложения внутри одного направления, с самостоятельными страницами. Go показывается как готовящееся направление, запись закрыта. Не добавлять отдельные продающиеся курсы по Kafka, архитектуре или многопоточности: пока это темы Advanced.

Доверие строится на опыте автора, ясной программе и демонстрации задач. Не добавлять числа выпускников, зарплаты, трудоустройства, отзывы, звёздные рейтинги, логотипы работодателей, гарантии работы, дипломы, сертификаты, партнёрства и стажировки без подтверждения владельца.

Программа ниже — предложение к согласованию. Наличие темы в макете не подтверждает готовность материала или включение услуги в договор. Ревью и обсуждение — предлагаемый учебный процесс; частота, объём, сроки ответа и длительность сопровождения ещё не утверждены. Не публиковать без проверки владельцем.

## 3. От потребности к задаче

| Ситуация посетителя | Предлагаемая практика | Проверяемый результат |
|---|---|---|
| По уроку получается, самостоятельно сложнее | Задача с требованиями и критериями, без готовой последовательности действий | Самостоятельное решение и объяснение |
| Трудно разобраться в существующем проекте | Запуск репозитория, поиск точки входа, чтение зависимостей, небольшое изменение | Изменение без нарушения соседнего поведения |
| Ошибка воспроизводится не всегда | Сбор признаков, минимальный сценарий, отладка и тест | Воспроизведение и проверка исправления |
| SQL знаком, поведение данных неясно | Транзакции, ограничения, индексы, конкурентные запросы | Объяснение целостности и компромиссов |
| Kafka знакома только в успешном сценарии | Повторная доставка, ошибка обработки, контракты событий | Проверка повтора и сценария сбоя |
| Многопоточность осталась на уровне терминов | Общие данные, синхронизация, гонка, безопасная обработка | Тест и объяснение выбранного механизма |
| Проект есть, рассказать о нём трудно | README, схема, описание альтернатив и демонстрация | Проверяемый рассказ о собственной работе |
| Неуверенность на интервью | Технический разбор, задачи и объяснение опыта | Персональный список тем и упражнений |

Не использовать публичные формулировки «после плохих курсов ничего не умеешь», «везде учат устаревшему» и «мы гарантированно доведём до middle». Не обещать коммерческий опыт за учебный проект.

## 7. Каталог и сравнение Java

Каталог H1: «Выбери направление и свой уровень».
Описание: «Java — два маршрута обучения. Английский — у нашего партнёра. Go — готовится».

Фильтры с постоянными метками:
- «Направление»: Все, Java, Английский, Go.
- «Подготовка»: Любая, С нуля, Есть основы Java.
Семантика: выбранный уровень относится к Java; при конкретном выборе уровня показывать Java-маршруты. Не приписывать партнёрскому английскому неизвестный уровень. На фильтре Go показывается карточка «Скоро», а не ошибка. Комбинация Go + конкретный уровень не должна выглядеть доступным курсом: пустая выдача и сброс.
Сброс: очистить оба фильтра. Пустая выдача: «По этим параметрам программ пока нет» / «Сбросить фильтры». Роль и статус из кабинетов сюда не переносятся.

Карточки Java включают уровень, краткое содержание, требования, «Подробнее» и «Поступить на курс». Не добавлять фиктивные цены. У английского только переход к партнёру. У Go нет ссылки поступления.

Страница /courses/java:
H1: «Два маршрута. Одна цель — понимать свою работу».
Описание: «Выбери старт по своей подготовке. Advanced не требует повторять весь путь с нуля».
Сравнение:
- Начало: без опыта / ООП, коллекции, SQL, основы HTTP и Git.
- Основная работа: упражнения и первый backend / изменение существующего проекта и сложные сценарии.
- Темы: основы и backend / конкурентность, события, диагностика и архитектура.
- Результат: собственный проект с понятным запуском / проверенные изменения, тесты и обоснования.
- Действия: открыть программу каждого маршрута.
Помощь: «Не уверен, какой маршрут выбрать?» / «Обсудить подготовку». Это заявка, не обещание автоматической оценки уровня.

## 8. Страница «Java с нуля»

Надзаголовок: «ДЛЯ НАЧИНАЮЩИХ».
H1: «Java с нуля: начни с понимания».
Описание: «От первой программы к backend-приложению: изучай тему, решай задачи и проверяй результат».
Кнопки: «Поступить на курс», «Посмотреть программу».
Метки: «Без опыта программирования», «Практика по темам».

H2: «Что входит в маршрут».
- Java Core: синтаксис, ООП, исключения и стандартная библиотека.
- Работа с данными: коллекции, файлы, SQL и PostgreSQL.
- Backend: HTTP, REST API и Spring Boot.
- Практика и разбор: задачи, тесты и объяснение решений.

H2: «Программа обучения». В дизайн-концепции пометка «Проект программы».
1. Первые программы: переменные, условия и циклы. Практика — небольшие консольные задачи.
2. ООП, исключения и файлы. Практика — приложение с моделями данных и обработкой ошибок.
3. Коллекции, Generics, Stream API, Optional и основы сложности. Практика — обработка наборов данных и выбор структуры.
4. Git, SQL и PostgreSQL. Практика — история изменений, запросы и целостность данных.
5. HTTP, Spring Boot и REST API. Практика — endpoints, валидация и работа с базой.
6. Тестирование и запуск приложения. Практика — JUnit, проверки API и воспроизводимый запуск, безопасное хранение конфигурации без секретов в репозитории.
7. Итоговый backend-проект. Практика — последовательное развитие приложения, README и демонстрация. Завершение — подготовка к первому техническому интервью: объяснить собственный проект, повторить базовые темы, описать учебную работу в резюме без выдуманного коммерческого опыта.

Темы, задания и готовность материала уточняются владельцем. Не включать все advanced-темы в начальный курс ради длинного списка технологий. Точная версия JDK и Spring согласуется отдельно; макеты не закрепляют случайную версию зависимости. В учебных Java-примерах использовать явные типы, без var.

H2: «Что останется после обучения».
- «Собственный код и история изменений»: решения и последовательность работы в Git.
- «Backend-проект с README»: описание задачи, запуск и используемые инструменты.
- «Тесты и разбор ошибок»: проверки освоенных сценариев.
- «Понимание следующих шагов»: темы, к которым стоит вернуться или перейти дальше.

Это артефакты работы ученика, а не обещание бессрочной лицензии на платформу. Условия сохранения репозитория и доступа к материалам после курса должны быть закреплены отдельно.

## 11. Английский и Go

Английский — партнёрское направление. Не создавать впечатление, что преподаватель Java проводит английский. Программа, цена, расписание, оплата и правила школы партнёра находятся у партнёра, пока не согласована иная интеграция.

Ссылка на внешнюю страницу сопровождается значком и доступным названием. Рекомендуется открывать в той же вкладке, чтобы не навязывать новое окно. Если владелец выберет новую вкладку, явно обозначить это в доступной подписи.

Дубли: компактная ссылка в шапке, карточка каталога, тематическая вставка Advanced, подвал. Не выводить четыре рекламных блока подряд на одном экране.

Адрес партнёра ещё не предоставлен. Не подставлять случайный домен и не выпускать кнопку с href=#. До публичного запуска адрес обязателен.

Go: силуэт абстрактного персонажа/символа, маленький замок, подпись «Скоро». Сохранять читаемость, не уменьшать opacity всей карточки. Нет таймера, даты запуска, оплаты, заявки и обещания готовых уроков. В декоративном силуэте нет обязательной анимации; на hover допустима лёгкая подсветка контура.

Java: одна форма, маршрут предвыбран по странице. Поля: «Имя», «Email», «Маршрут Java» (С нуля / Advanced / Пока не знаю), необязательное «Что хочешь обсудить?». Обязательное согласие на обработку данных с реальной ссылкой на утверждённую политику. Без автоматически отмеченного согласия и без подписки на рекламу.

Заголовок: «Поступить на курс».
Пояснение: «Оставь контакт — обсудим программу и условия обучения».
Кнопки: «Отправить заявку», «Отмена».
Обязательные ошибки: «Введите имя», «Введите корректный email», «Выбери маршрут», «Нужно согласие». Правила длины и нормализации задать по API, не угадывать их по макету.

Состояния:
- Default: ошибок нет до попытки отправить или согласованной проверки после взаимодействия.
- Invalid: ошибки возле полей, общий итог по необходимости, переход к первой ошибке.
- Sending: «Отправляем…», значения сохраняются, повтор недоступен.
- Подтверждённый отказ/неуспешная отправка: «Не удалось отправить заявку. Введённые данные сохранены» и «Повторить».
- Неизвестный исход при таймауте: «Не удалось подтвердить отправку». Нельзя обещать, что заявка отсутствует. Безопасный повтор только при согласованном механизме идемпотентности/проверки исхода.
- Success только по ответу сервера: «Заявка отправлена». «Это ещё не зачисление на курс». Кнопка «Закрыть».
- Никакого фиктивного успеха по таймеру и отправки в консоль вместо реального канала.

Английский не отправляется в неподтверждённую CRM академии: партнёрская ссылка ведёт на сайт Галины. Общая шапка «Поступить на курс» открывает Java-заявку с выбором маршрута; в форме отдельная строка «Ищешь английский? Курсы Галины Свириной ↗». Это устраняет неоднозначность.

Пока endpoint заявки, юридический текст и политика не согласованы, форма остаётся дизайн-состоянием. Не запускать сбор персональных данных через случайный сервис.

Нет scroll hijacking, закрепления секции на несколько экранов, параллакса текста, магнитных кнопок и мерцающего курсора на всём сайте. Не разделять каждое слово H1 на сотни DOM-узлов ради появления.

Системная настройка движения: CSS media feature prefers-reduced-motion: reduce и соответствующая проверка matchMedia в будущих JS-контроллерах. Реагировать на событие change этой настройки; при размонтировании удалять слушатели и отменять незавершённые анимации.

При reduced motion: без сдвигов, масштаба, скролл-анимаций и цикла схемы; содержание сразу видно, transitions убрать или сократить до0. Появление контента не зависит от JS. Анимация — progressive enhancement: исходно контент доступен, невидимость включается только после готовности контроллера.

## 18. Обязанности будущих скриптов — без реализации на этом этапе

ThemeController:
1. До первого отображения выбрать сохранённую тему либо системную.
2. Безопасно обработать недоступный localStorage.
3. Менять только токены темы, не пересоздавать страницы и форму.
4. Реагировать на смену системной темы, пока нет ручного выбора.
5. Уведомлять кнопки о новом доступном действии, не создавать вспышку неправильной темы.
6. Не обещать синхронизацию с кабинетом на другом домене без отдельного контракта.

NavigationController:
- Управлять desktop-dropdown и mobile-dialog.
- Закрывать после перехода, клика вне применимого меню и Escape.
- Возвращать фокус инициатору; не удерживать desktop-dropdown как модальный.
- Хранить прежнее положение страницы при блокировке фона.
- Не терять фокус при смене breakpoint.

RevealController:
- Использовать IntersectionObserver; один экземпляр обслуживает элементы.
- После завершения отключать наблюдение за элементом.
- При отсутствии API или reduced motion показывать всё.
- Не ставить обработчик scroll с чтением размеров каждого элемента в каждом кадре.

AccordionController:
- Разделить состояние модулей и FAQ.
- При закрытии не оставлять фокус в скрытом содержимом.
- Измерять высоту при необходимости; отменять предыдущий переход при быстром клике.
- После изменения текста/ширины пересчитать естественную высоту.
- При reduced motion менять состояние сразу.

ApplicationController:
- Предвыбор маршрута по источнику кнопки.
- Валидация по утверждённому API, защита от двойной отправки.
- Состояния editing/invalid/sending/failed/unknown/succeeded.
- Success только по реальному подтверждению.
- Не стирать ввод при сетевой ошибке и смене темы.
- Не отправлять содержимое формы в аналитику или URL.
- Идемпотентность и восстановление неизвестного исхода зависят от backend.

DialogController:
- Доступное имя и модальность, focus trap, inert-фон, scroll lock.
- Начальный фокус на заголовок либо первое подходящее поле.
- Escape/крестик/фон закрывают в обычном состоянии.
- Во время отправки закрытие временно недоступно с пояснением «Заявка отправляется. Дождись результата». Это не механизм отмены серверного запроса.
- После ошибки закрытие снова доступно. Уход со страницы не означает отмену операции.

CourseCatalogController:
- Предсказуемая комбинация фильтров, сохранение в URL при необходимости.
- Возврат из курса сохраняет параметры и позицию.
- Старый сетевой ответ не заменяет новую выдачу, если каталог динамический.

HeroSequenceController:
- Запустить один цикл после готовности страницы, только при видимости и разрешённом движении.
- Остановить при скрытой вкладке, уходе со страницы и reduced motion.
- Декорация не получает фокус и не мешает кликам.
- Для простой схемы достаточно CSS/SVG; canvas/WebGL не обязательны.
Конкретный фреймворк и библиотеку анимаций не назначать до изучения репозитория. Не добавлять GSAP, Lenis или Framer Motion только потому, что они упоминаются на сайте-референсе.

## 19. Доступность и адаптация

Все функции доступны с клавиатуры. Skip-link «К содержимому». Один H1, логичная иерархия H2/H3, landmark header/nav/main/footer. Видимый focus не обрезается overflow карточки.

Минимум44×44 CSSpx для действий на touch. Состояния различаются текстом/иконкой. Читаемость ссылок и форм проверяется по финальным токенам, а не по впечатлению от PNG.

На320px и при увеличении текста200%: одна колонка, кнопки растут и переносятся, шапка допускает компактный вариант, статусы не обрезаются, нет горизонтальной прокрутки страницы. Большие схемы преобразуются в вертикальную последовательность. Декоративное изображение может уменьшаться, но не уменьшает основной текст.

Модальные панели доступны при экранной клавиатуре; действия находятся в вертикальной прокрутке. Не прятать отправку за фиксированным footer. Движение не является единственным способом понять состояние.

Ошибка поля связана через aria-describedby, invalid. Ход отправки и успех объявляются через ненавязчивый live-region; значимые ошибки — явно. Не переносить фокус при каждом изменении текста. При успехе фокус на заголовок результата.

Проверка реализации: keyboard-only, Escape/returnfocus, zoom200%, ширины320/390/768/1024/1440, обе темы, reduced motion, отключённый JS для основного содержания. PNG не подтверждает прохождение этих проверок.

## 21. Инструкция Codex: порядок реализации после утверждения

1. Изучить существующий frontend и его маршрутизацию, общие компоненты, авторизацию и дизайн-токены. Не создавать второй проект без необходимости.
2. Использовать только актуальные референсы. Сначала согласовать текст и программу, особенно выходные артефакты и сопровождение.
3. Создать общую систему двух тем, типографики, кнопок, карточек, меню, accordion и заявки.
4. Реализовать самостоятельные страницы по карте, сначала главную и обе Java-программы. Не ограничиваться первым экраном.
5. Каталог и сравнение не объединять случайным образом. Java — одно направление, два маршрута; английский партнёрский; Go готовится.
6. Все пользовательские тексты русские; имена технологий и Advanced сохраняются. Не помещать бизнес-тексты только в PNG.
7. Подключать реальный endpoint заявки только после согласования контракта. Не делать ложную отправку ради демонстрации.
8. Добавлять движения после устойчивой статической компоновки и доступности.
9. Проверить обе темы на одинаковых данных, мобильную компоновку, focus и 200% текста.
10. Сверить все ссылки и конфигурацию перед публикацией. Не публиковать случайные контакты и неизвестный адрес партнёра.
11. Предъявить результат для проверки владельцу; публикация не входит в текущий дизайн-этап.

Внешний вид и поведение определяются этой спецификацией. Если PNG противоречит HEX, названиям, программе, статусам либо переходам, использовать текстовую спецификацию. Незначительное зерно или градиент, возникшие при генерации, не становятся обязательным эффектом реализации.

## 22. Критерии приёмки дизайна и будущего frontend

- На главной с первого экрана понятно, что основное направление — Java с двумя уровнями.
- Из любого desktop-экрана доступны курсы, заявка, тема и вход.
- Английский виден как партнёрское направление Галины, не собственный Java-продукт академии.
- Go узнаваем, читаем и явно обозначен как готовящийся.
- У маршрутов разные требования, содержание и практические результаты.
- Advanced не обещает работу, грейд или коммерческий стаж.
- В описании есть не только технологии, но и конкретные задачи и выходные артефакты.
- Никаких придуманных достижений, цен и коммерческих условий.
- Тема не теряет введённые данные и положение страницы.
- Hover не является единственным способом открыть содержание.
- Нет горизонтальной прокрутки всей страницы, в том числе320px и200% текста.
- Анимации отключаемы через системную настройку.
- Сбой заявки сохраняет ввод; неизвестный исход не маскируется под отказ или успех.
- Работа кабинетов и их продуктовые правила не меняются этим дизайном.

## 23. Решения, которые ещё нужны от владельца и backend

Продукт:
1. Утверждение программы обоих маршрутов и готовности материалов.
2. Что входит: ревью, индивидуальные/групповые встречи, ответы на вопросы, формат и длительность сопровождения.
3. Срок обучения, нагрузка, начало, стоимость, порядок оплаты и возвратов.
4. Что доступно после окончания: материалы, обновления, задания, проверка, репозитории и консультации; на какой срок.
5. Конкретный объём подготовки к интервью РФ/международного направления.
6. Реальные подтверждённые сведения об авторе, фотография и материалы для демонстрации.
7. Ссылка и утверждённое название программ Галины, модель обработки обращений.
8. Реальный контактный канал, юридическое лицо/ИП, политика данных и условия обучения.

Backend/frontend:
1. Endpoint заявки, обязательные поля, ошибки валидации и ограничения длины.
2. Идемпотентность, повтор при таймауте, способ проверки неизвестного исхода.
3. Что означает успешный ответ и куда попадает заявка. Отправка письма не равна доставке.
4. Адрес существующего кабинета и допустимые переходы авторизации.
5. Где хранится контент каталога и программ, есть ли CMS/API или статические данные.
6. Согласование сохранения темы между публичным сайтом и кабинетом, если домены различаются.

## 26. Ресурсы, устойчивость и передача в разработку

Графика первого экрана не должна задерживать чтение текста. Задать размеры изображений заранее, чтобы они не сдвигали страницу при загрузке. Подготовить адаптивные WebP/AVIF и резервный формат по поддержке браузеров. Декоративные изображения ниже первого экрана загружать отложенно; при ошибке загрузки сохраняются текст, размеры карточки и действия. Содержательные изображения получают alt, чистая декорация — пустой alt.

Шрифт с кириллицей хранить согласно лицензии, подключать только нужные насыщенности; определить стратегию font-display и fallback. Не подгружать несколько разных семейств для каждого заголовка. Не вырезать кириллицу из font-subset.

Сценарии анимации должны очищать observers, таймеры, requestAnimationFrame и listeners при уходе со страницы. В скрытой вкладке и вне viewport тяжёлые эффекты остановлены. Анимировать преимущественно transform/opacity, не пересчитывать layout в цикле. Высоту accordion измерять по действию, а не непрерывно. Простая иллюстрация не требует WebGL.

Загрузка страницы курса: при реальном ожидании данных показывается skeleton без прыжка компоновки. Ошибка — «Не удалось загрузить программу» / «Повторить», с сохранением URL и темы. Если данных нет, не подменять курс выдуманной программой. Неизвестная страница — «Страница не найдена», «В каталог курсов» и «На главную».

Базовые заголовки вкладок: «Advent Academy — Java и практика разработки», «Курсы — Advent Academy», «Java с нуля — Advent Academy», «Java Advanced — Advent Academy». Description соответствует видимому предложению, без гарантий и несуществующих достижений. Для партнёрской ссылки не создавать фиктивную локальную страницу с копией сайта Галины.

Проверку проводить по страницам и сценариям: выбор маршрута → программа → требования → заявка → ошибка/успех; каталог → фильтр → курс → назад; тема при заполненной заявке; Escape и возврат фокуса; мобильное меню при смене ширины; reduced motion; отсутствие JavaScript для чтения основного содержания.

В пакет входят PNG с читаемыми именами и эта спецификация. PNG задают композицию и характер. Текст задаёт точные требования, состояния, русские формулировки и ограничения. Перед реализацией Codex должен перечислить обнаруженные расхождения с существующим проектом и предложить минимальное согласованное изменение, не перестраивая кабинеты ученика и управления.
