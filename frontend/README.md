# Advent Academy — frontend

Next.js (App Router), React, TypeScript и Tailwind CSS. Утверждённый дизайн кабинета
используется для реального обучения на `/`. Демоверсия с localStorage и меню
состояний остаётся на `/demo`; демонстрационные данные не переносятся в реальные аккаунты.

## Запуск

Node.js 24 LTS (`.nvmrc`). В `frontend/.env.local` нужны:

```dotenv
API_GATEWAY_URL=http://localhost:8090
FRONTEND_ORIGIN=http://localhost:3000
SESSION_ENCRYPTION_KEY=<base64 от 32 случайных байт>
MEETING_SIGNALING_URL=ws://localhost:8090/ws/meetings
```

Ключ: `openssl rand -base64 32`. Он хранится только на сервере и должен сохраняться
между перезапусками. При его смене пользователи входят повторно.
`FRONTEND_ORIGIN` должен точно совпадать с адресом браузера, включая порт;
для HTTPS cookie автоматически получает Secure.

```bash
cd frontend
npm ci
cp -n .env.example .env.local
npm run dev
```

После заполнения конфигурации открой http://localhost:3000. Для другого порта
измени `FRONTEND_ORIGIN` и используй `npm run dev -- --port 3001`.
Backend и gateway должны быть запущены отдельно.

## Реальный кабинет

Работают вход (включая MFA), профиль, выход, назначенные курсы, программа,
опубликованные Markdown-материалы и вложения, завершение уроков и серверный прогресс.
Курсы назначаются через API владельцем курса/редактором/администратором;
сама регистрация курс не назначает. UUID ученика берётся из user-service.
Последовательность уроков и запрет завершения обязательного задания проверяет сервер.
Работают условия обязательных заданий, сдача HTTPS-ссылки с комментарием,
повторная отправка после доработки, история и результат проверки. Принятие завершает
урок на сервере и открывает следующий. «Задания» и «Требует внимания» используют
реальные статусы. Для INSTRUCTOR/ADMIN/CONTENT_EDITOR доступен экран «Проверка заданий»;
преподаватель видит свои курсы, собственную работу проверять запрещено.
Работают постоянное расписание, ближайшая встреча, управление преподавателя и
групповой видеозвонок до 8 участников. Учеников выбирают из назначенных курсу.
Преподаватель запускает занятие; отмена и завершение закрывают подключения.

В браузере нет доступных JavaScript access/refresh-токенов: они находятся в
зашифрованной AES-GCM HttpOnly/SameSite cookie. Запросы идут через Next.js BFF
с ограниченным списком путей и проверкой Origin для изменений. Сессия обновляется
через `/api/auth/refresh`; выход отзывает её refresh-токен и удаляет cookie.
Выданный access JWT действует до своего срока истечения (по умолчанию 15 минут).
Текущая координация refresh рассчитана на один standalone-процесс frontend;
перед запуском нескольких экземпляров нужен общий серверный session/rotation store.
Стандартный лимит user-service по IP за gateway также требует настройки доверенного
прокси/лимитов для многопользовательского развёртывания (ADR 0005).

Опубликованные assets сохраняют действующий публичный backend-контракт.
Видео до 10 MiB можно загрузить как asset; отдельного стриминга или приватного
видеохостинга этот спринт не добавляет. HTML материалов очищает content-service;
браузер не использует HTML из `design-reference/`.

## Проверки

```bash
npm run check
npm run build
npm run start
```

`check`: Biome и TypeScript. Сборке нужен доступ к Google Fonts.
Если окружение запрещает внутренний порт Turbopack: `npm run build -- --webpack`.
Docker production-сборка проверена с обычным `npm run build`.

Изолированный сценарий через настоящий браузер, Java-сервисы, gateway и PostgreSQL
описан в [спринте](../docs/frontend/sprint-1.md). Скрипт `npm run test:runtime`
использует Playwright и установленный Chrome (`CHROME_PATH`), синтетические
аккаунты и свежий тестовый курс. Он проверяет cookie/CSRF, прогресс, refresh,
выход и повторный вход, запрет чужого курса, мобильную ширину и отдельное демо.

## Docker

Заполни `SESSION_ENCRYPTION_KEY` в корневом `.env` тем же способом;
`FRONTEND_ORIGIN` по умолчанию http://localhost:3000. Сначала запусти backend/gateway,
затем из корня:

```bash
docker compose --profile frontend up -d --build frontend
```

В контейнере `API_GATEWAY_URL=http://api-gateway:8090`.
`GET /api/health` отвечает 200 только при настроенном ключе сессии и готовом gateway;
Compose использует этот endpoint для healthcheck. `/demo` можно открыть без сессии.
Самостоятельная сборка: `docker build -f frontend/Dockerfile -t advent-frontend .`.

## Структура

- `src/components/academy.tsx` — общий дизайн кабинета и демо.
- `src/components/live-academy.tsx` — реальные данные и формы входа.
- `src/lib/learning.ts` — frontend-типы и преобразование ответов API.
- `src/lib/server-session.ts` — серверная сессия и вызовы gateway.
- `src/app/api/` — BFF и readiness.
- `src/lib/demo.ts` — изолированные демонстрационные данные.
- `scripts/` — проверки на отдельном runtime-стенде.

## Задания (спринт 2)

[План, контракты и проверки](../docs/frontend/sprint-2.md).
Черновик решения хранится отдельно по пользователю/курсу/уроку; access/refresh-токены
в localStorage не сохраняются. При запрете хранилища форма предупреждает о сохранении
только до закрытия страницы. После потери ответа повтор использует тот же requestId.
Обновить результат проверки и прогресс можно кнопкой «Обновить статус»; уведомления
и автоматический polling в этот спринт не входят.

Очередь преподавателя фильтруется по статусу и имеет страницы по 20 работ.
При доработке нужен комментарий; решения защищены версией от конкурентной проверки.
Условия задания задаются через API владельцем компонента/редактором и не меняются
после первой сдачи. Старый обязательный урок без условия требует его заполнения.
BFF принимает JSON сдачи/проверки до 32 KiB, включая запросы без Content-Length.
Для проверки на отдельном стенде: `npm run test:assignments` (команды подготовки в плане).


## Групповые занятия (спринт 3)

[План, API и изолированная проверка](../docs/frontend/sprint-3.md).
`MEETING_SIGNALING_URL` — адрес gateway, доступный браузеру; при HTTPS используется
`wss://`. `MEETING_ALLOWED_ORIGINS` в meeting-service должен включать точный
`FRONTEND_ORIGIN`. Камера и микрофон запрашиваются после нажатия «Подключиться».
Для настоящих устройств нужен HTTPS (localhost допускается браузером).

meeting-service теперь требует PostgreSQL и `CONTENT_SERVICE_URL`; user-service
тоже использует `CONTENT_SERVICE_URL`, чтобы проверить право на список учеников.
После изменений user-service сначала выполняют `./gradlew :user-service:bootJar`:
его Dockerfile копирует готовый JAR. Миграция расписания создаёт отдельную схему
`meeting`, не переносит старые временные комнаты в расписание.

После перезапуска сервиса расписание сохраняется; открытые звонки требуют
«Переподключиться». WebRTC mesh соединяет каждую пару участников. Проверка
`npm run test:meetings` использует три браузерных контекста с синтетической камерой,
временный PostgreSQL и перезапускает только контейнер своего тестового проекта.
Для соединений через разные сети следует настроить ICE/TURN в meeting-service;
внешний TURN и производительность группы на реальных устройствах проверяются
отдельно перед публичным запуском. Несколько meeting-service требуют общей
сигнализации/состояния подключений или маршрутизации одной комнаты на один экземпляр.
